# azionapi-php-sdk

Official Azion SDK for the PHP programming language.

The repository contains one PHP client per Azion API product. Every client
is generated by [OpenAPI Generator](https://openapi-generator.tech) from the
product's OpenAPI document and is self-contained: it has its own
`composer.json`, sources (`lib/`), API reference (`docs/`) and README.

## Requirements

- PHP 7.4 or later, with the `curl`, `json` and `mbstring` extensions
- [Composer](https://getcomposer.org/)
- `guzzlehttp/guzzle` ^7.3 and `guzzlehttp/psr7` ^1.7 or ^2.0 (installed by Composer)

## Installation

The packages are not published to Packagist. Check out a release tag and run
Composer inside the package directory you need:

```sh
git clone --branch v0.84.0 https://github.com/aziontech/azionapi-php-sdk.git
cd azionapi-php-sdk/personal_tokens
composer install --no-dev
```

Then include the package autoloader:

```php
require_once '/path/to/azionapi-php-sdk/personal_tokens/vendor/autoload.php';
```

All packages use the same `OpenAPI\Client` namespace, so load only one
package per autoloader (per process).

## Usage

Configure the API token, build the API class and call an endpoint. For
example, with `personal_tokens`:

```php
<?php
require_once __DIR__ . '/vendor/autoload.php';

$config = OpenAPI\Client\Configuration::getDefaultConfiguration()
    ->setApiKey('Authorization', 'YOUR_API_TOKEN')
    ->setApiKeyPrefix('Authorization', 'Token');

$api = new OpenAPI\Client\Api\PersonalTokenApi(new GuzzleHttp\Client(), $config);

try {
    $result = $api->listPersonalToken();
    print_r($result);
} catch (OpenAPI\Client\ApiException $e) {
    echo 'API error: ', $e->getMessage(), PHP_EOL;
}
```

## Development

The package directories are generated code. They are updated by automated
`generated-sdk` pull requests ("Auto-Generated SDK" commits), so do not edit
them by hand: changes belong in the OpenAPI documents or generator settings.
Repository-level files (tests, workflows, documentation) are maintained here.

Run the functional tests (Node.js 22 and Docker required):

```sh
cd tests/vitest
npm ci
npm test
```

The suite installs the shared runtime dependencies once (pinned Composer
image, `tests/vitest/harness/composer.lock`) and runs a small PHP harness in
a pinned `php:8.3-cli` image. It loads every package, builds every API class,
checks that each endpoint documented in the package README exists, and calls
endpoints of several packages against a local HTTP double to verify routing,
token authentication, headers and model deserialization.

Linting: `php -l` on every PHP file and ShellCheck on the `git_push.sh`
scripts (`.github/workflows/ci-code-quality.yml`).
